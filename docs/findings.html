Decided

How it will work

  • Versioned code on GitHub Pages. The MFL header points at …/fuadmflsite/v1/fuad.js. New versions start dark; activating and reverting are one-line header edits; each season's site pins its own version.
  • Franchise salaries switch automatically: last season's snapshot until the week 1 kickoff, a live projection until the week 12 trade deadline, then this season's snapshot.
  • A daily GitHub job logs in as commissioner, takes the franchise snapshot and keeps a chore log, both on its own league-data branch since master is protected, and keeps itself alive.
  • League logic is written once, shared by the page and the job.

Ruled out

Considered and set aside

  • A separate companion site. A second destination, and it can't tell who's viewing.
  • A proxy for MFL's API. Against MFL's terms.
  • Leaving MFL. Would give up the custom rules.
  • A public league-history site. Optional, after A and C.
Ground rules

From your decisions

  • Works well in a phone browser.
  • No new navigation layer; the custom tabs stay.
  • Within MFL's rules.
  • As few chores to remember as possible.
